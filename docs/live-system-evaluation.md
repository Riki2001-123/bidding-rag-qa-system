## 发现与兼容修复

1. **空筛选参数误走旧检索分支。** 路由传入 `region=None` 等参数，却被视为存在筛选条件。旧路径为招标和企业加载了约百万条 BM25 片段；本机可用物理内存一度约 0.3 GB。忽略 None/空字符串后，纯关键词请求进入已有 `high_recall_search` 路径。未改检索模型、召回算法、业务授权或非空筛选语义。
2. **大批次重排。** 增加 `RERANKER_BATCH_SIZE`，默认 4，保留全部候选及同一评分、排序规则；本机启动脚本限制 CPU 推理线程。真实查询仍有明显等待，不能用作公开性能承诺。
3. **流式会话 ID 缺失。** 延后转发 done 事件，等待源流结束及数据库保存成功，回传真实 session_id；保存失败发 error。连续两轮验证同一服务端会话。
4. **模型失败伪装完成。** SSE 模型不可用或中途异常向上游传播，由问答服务返回安全 error；不拼接 fallback 并当作成功保存。对应失败场景由受控单元测试覆盖，真实供应商故障未人为制造。非流式 `/chat/query` 的原有 fallback 行为不在此次修复范围。

本机单次耗时（包含当时负载，不是基准）：首轮政策/招标/企业搜索为 12.30 / 141.69 / 52.23 秒；修复后首次为 28.63 / 6.99 / 31.34 秒。政策首查含模型与索引预热；不同路径和系统负载不适合做严格横向性能比较。修复后的 API 政策问答约 56.23 秒、追问约 110.04 秒；没有验收并发或延迟 SLA。

浏览器初次脚本错误来自 Ant Design 图标加入按钮可访问名称，以及将返回按钮定位为链接；修正测试定位并重跑相关项后通过。来源截图增加等待抽屉动画。未将这些脚本失败作为产品成功；原始与复测报告均保留。

## 质量失败项

- **首轮答案并非逐项受证据约束。** 测试问题询问政府采购法适用范围；返回来源存在且标题匹配，但模型明确说核心法条原文不在本轮证据中，并加入证据外推断。不能把这些回答标成严格的证据支持答案。
- **省略主题的追问没有稳定承接检索主题。** 问题“请把刚才的适用范围归纳成两点。”确实复用会话 279，但检索引用转为土地、产权等不相关政策，模型只能表示当前证据不足。会话持久化通过，追问的检索相关性未通过。网页测试的追问明确写出“政府采购法”，其功能检查不能替代省略主题的语义验收。

这两项已回写 SPEC 的下一版候选。本版没有扩大到检索缓存生命周期、Query Rewrite、答案约束和评测算法修改。

## 未验证与限制

- 数据库没有附件：实际文件下载、附件内容及跨角色授权未验证；只测未登录及不存在附件的接口行为。
- 业务记录目前没有 private/internal 级别样本：这些真实级别的拒绝/允许组合未验证。314 条政策访问级别 NULL，只有管理员可见；普通角色按当前权限只能看到可访问记录，本版未擅自开放。
- 空筛选修复覆盖当前统一检索；包含关键词与真实非空筛选的旧路径仍可能加载大 BM25 索引，需下一版处理。按 stage 单独筛选及筛选保留单测已通过。
- 非流式问答的远程失败处理、真实模型供应商故障、共享浏览器的账号历史隔离、全量质量指标、并发、负载、公网部署未验证。当前结果不等同于整个现有后端测试套件或生产安全评审全部通过。
- 默认开发账号仍存在；公开真实服务前需要独立配置账号与部署规格。公开展示和虚构演示可独立托管，业务数据与密钥不随静态前端公开。
