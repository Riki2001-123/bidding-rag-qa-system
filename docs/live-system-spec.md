# 真实系统联调 V1 — SPEC

日期：2026-10-06。用户授权：启动本机真实系统并做联调验收。流程：SPEC → IMPLEMENT → TEST → EVALUATE。

## 范围

使用现有 MySQL、Milvus、D 盘缓存的 BGE 模型及根目录 `.env` 配置的模型服务。验证真实 API 与浏览器界面，不用样例或受控响应代替真实结果。允许为阻断验收的问题做最小兼容修复并复测；不重建百万条业务索引、不改变检索算法、不发布或推送。

## 操作边界

- 数据和向量索引保留。仅登录及正常问答产生必要的账号密码哈希升级和测试会话；不修改业务记录、权限或已有历史。验收问题加唯一标识，记录新增会话 ID。
- 使用已有初始化账号（若仍有效）；不得重置现有密码。登录不可用时请求用户提供可用账号。
- 模型调用仅限验收所需少量问题。密钥、密码、token 不写入报告或截图。
- 缓存、日志、浏览器数据及测试产物在 D 盘，本项目产物放 `dist/live-system-tests/`；文档在 `docs/`。
- 未遇到的权限类型、缺失附件或不可用依赖标记为未验证，不创建业务数据补齐验收。
- 首轮发现本机仅约 0.3 GB 可用内存，大批次重排使检索耗时过长。本版兼容修复增加可配置的 `RERANKER_BATCH_SIZE`（默认 4），只改变推理批次，不改变候选、模型或排序逻辑；验证分批仍保留全部候选并正确排序。
- 首轮实测进一步发现：路由传入值为 None 的可选筛选字段，导致纯关键词搜索误走旧筛选路径，构建约百万条 BM25 内存索引。本版忽略空筛选字段，使请求进入已有 high_recall_search 路径；真实非空筛选继续保留。复测三域纯关键词与非空筛选，不改变已有检索算法。

## 验收条件

1. MySQL、Milvus、Embedding 真实可用，记录集合数量、维度、真实模型加载状态；进程的缓存路径在 D 盘。
2. 未登录业务路由跳到登录；API 无 token/错误 token 返回鉴权失败；错误密码失败；真实登录进入 `/chat`。
3. 政策 SSE 包含真实分段、最终回答和来源；引用记录能对应 MySQL 原文；模型错误明确提示，不被记录为成功生成。
4. SSE 回传持久化后的 session_id；连续两轮使用同一会话，服务端保留正确的用户/助手消息。若存在兼容性缺口，最小修复后验收。
5. 停止生成中断请求、停止界面生成状态并保留已收到文本；不将未完成回答当完成回答。
6. 政策、招标、企业真实检索与来源详情；空查询结果；已存在附件按实际文件及权限验证。
7. 可用真实角色的检索结果符合已有项目与访问级别限制；不得为了测试修改授权。
8. 桌面、手机、语言切换、键盘和来源抽屉；真实数据保持原文；浏览器无未处理错误。
9. 修改涉及的后端测试、前端单元测试和生产构建通过，使用预览验证真实路由。

## 下一版候选

- 多轮证据衔接：首轮检索缓存尚无 session_id，省略主题的追问可能检索到无关领域记录。用明确主题与指代追问分别验收检索主题、上下文和引用一致性。
- 答案逐项溯源：本次真实回答出现未被返回证据直接支持的推断。建立小规模人工标注集，检测无依据结论及不相关引用；不把记录 ID 正确等同于答案正确。
- 政策数据治理：314 条政策 access_level 为 NULL，普通角色按现有权限不可见。明确每条数据授权和政策版本后再迁移，不擅自改成 public。
- 带真实非空筛选且含关键词的旧检索路径仍需独立评估；本版只修复空筛选误选分支，不改变筛选语义或检索算法。
- 聊天本地缓存按账号隔离、已有附件及内部/私有记录权限覆盖、部署环境容量和并发测试，按独立规格推进。
