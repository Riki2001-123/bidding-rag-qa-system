# GitHub Pages 展示发布 V1 — SPEC

日期：2026-10-06。用户授权：将首页和免登录样例部署到现有 GitHub 仓库的 Pages，提交、推送并发布；不部署真实后端。

## 范围

- 目标地址：https://riki2001-123.github.io/bidding-rag-qa-system/。使用现有 master 分支与 GitHub Actions 构建、部署，仅上传静态展示构建目录。
- 新增 pages 构建模式，Vite 资源 base 与 BrowserRouter basename 适配仓库子目录。正常本地构建仍保留真实登录和业务页。
- 公开构建只挂载首页、演示和真实系统说明页；不展示登录表单，不挂载真实业务组件，不访问业务 API、不读取或写入真实登录与聊天状态。说明页引导体验样例或联系 Riki，双语且明确真实数据服务未在此站点开放。
- /demo、/login、/chat、/search、/dashboard 生成目录 index.html，使 Pages 的静态服务器支持直接打开、刷新与 query 参数。未知页面使用 404.html 引导回首页。已知页面直接访问返回成功，不能把 404 页面正常渲染误记为已知路由部署成功。
- 四种虚构案例、追问、检索、引用、样例标识和语言记忆沿用 V1。无真实数据、密钥、模型文件、运行截图、日志或其他 dist 内容进入发布产物。
- 本机新增缓存、临时文件、Pages 构建和测试均在 D 盘 dist/pages-deployment/。GitHub 托管 runner 使用其 Linux 工作目录和 dist 子目录，不使用 Windows 路径。

## 验收

1. 正常单元和本地生产构建通过；pages 构建只包含公开组件和静态资源，产物范围检查通过。
2. 使用模拟 Pages 静态服务器，不做 SPA 回退；检查子目录首页与所有已知入口的直接访问、刷新及案例参数，响应成功且资源无 404。
3. 中英四案例、预设追问、未匹配问题、搜索空结果及引用一致；桌面/手机无横向溢出，键盘来源抽屉可操作。
4. 保留预置登录及聊天存储不变，所有公开路径零业务 API 请求；真实入口只有说明，没有可提交的登录表单。
5. 启用 Pages Actions 后提交发布，确认远端部署成功并对实际 HTTPS 地址复测主要入口和样例；截图与报告保留本机 dist。
