## 未验证与已知限制

- 未启动真实业务后端，本机 8000 端口在检查时未监听。真实登录、MySQL 数据/权限、Milvus 索引、Embedding、重排、模型生成及真实附件下载没有集成验证。受控响应不能替代这些检查。
- SSE 后端 `_persist_answer` 的返回值没有出现在流式响应中；新建 session_id 不回传。前端会使用返回的会话 ID，但当前新流式会话的服务端多轮连续性存在既有缺口。展示使用“会话管理”表述，未宣称已完成多轮联调。
- 找到既有本地评测报告，但其样本、范围与指标不支持原 README 中 93% Recall@10 和 35%→15% 幻觉率说法。本版撤下宣传数值，没有重新运行模型评测。
- 没有公网发布、实测静态托管商或检查 GitHub 主页是否提供额外联系信息；已核对应用链接目标。子目录托管不在 V1 配置内。
- 新首页改变 `/` 的含义：旧业务默认入口改为 `/chat`；登录成功跳转相应更新。旧前端聊天数据仍使用既有存储 key。
- 本机既有 npm 用户配置发出格式警告；构建正常。本任务没有迁移或清理系统配置。
