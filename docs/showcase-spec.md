# RAG 接单展示 V1 — SPEC

状态：V1 实现与前端验收完成，2026-10-06；真实后端联调未验证。流程：SPEC → IMPLEMENT → TEST → EVALUATE → 修改 SPEC → 下一版。

## 目标与边界

面向企业 AI 应用客户，以招投标业务为案例展示知识问答、业务数据查询和答案溯源。交付中英双语首页、免登录演示、真实系统界面升级、双语 README、截图和部署说明。仅本地实现与可部署构建，不发布、不推送、不修改后端接口或 RAG 算法。

后续授权（2026-10-06）：用户要求将已完成的 V1 同步到既有 GitHub 仓库 `Riki2001-123/bidding-rag-qa-system`。此项允许提交和推送源码、文档及展示截图；不包含公网网站部署。

## 页面与接口

- `/`：公开展示首页，包含产品预览、业务场景、已有能力、技术架构、可定制服务、体验/源码/联系入口。
- `/demo`：公开独立样例演示，四个案例：政策问答、项目筛选、企业查询、跨领域关联；每例有预设追问。样例搜索支持关键词、领域筛选、空结果及来源详情。
- `/login`、`/chat`、`/search`、`/dashboard`：真实系统；业务页继续要求鉴权。登录进入 `/chat`，提供返回首页入口。
- 默认中文，记住中英切换；真实记录和模型回答保持原文。Riki、GitHub 主页及 `Riki2001-123/bidding-rag-qa-system` 是对外身份与链接。
- 样例是虚构记录和双语预设答案，始终标注；只做明确匹配和预设追问，未知输入引导选择案例。模拟分段呈现需标注。演示不请求业务 API、不读取真实 token/聊天历史，内存会话刷新重置。
- 保持现有 auth/chat/search/attachments API 及权限。真实错误不伪装成功，不回退样例。真实来源只显示 API 已有字段，附件经鉴权下载。

## 视觉与内容

暖白、深色文字和蓝色重点；响应式布局，桌面来源侧栏/手机抽屉；可用键盘操作，移除无行为操作按钮。复用消息、检索与来源组件，路由延迟加载。隐藏内部库名，修正 FAISS 旧文案。已有能力与可定制服务分别标注；未获报告支持的性能数字和未确认经历不展示。README 英文为主、中文为辅，包含截图、两种运行模式、架构、正确启动路径、静态托管和路由回退。

## 验收

1. 后端关闭时公开页完整工作，无业务 API 请求；四案例及追问中英证据一致。
2. 未匹配问题、空搜索、筛选、来源展开、语言切换、复制与重置按规格工作。
3. 真实业务鉴权、登录跳转、SSE 分段/最终结果/停止/错误和搜索回归；缺依赖记为未验证。受控 HTTP 测试不能替代真实后端验证。
4. 桌面/手机、键盘、滚动、外链与深链检查；保存截图和测试报告。
5. 生产构建通过；构建预览可直接访问公开路由。
6. 新增缓存、临时文件与测试/构建产物在 D 盘；本项目产物在 `dist/`，README 用截图作为有意提交的文档资源。

## 下一版候选（不属于 V1，需独立确认规格）

- 流式会话连续性：后端持久化新会话后，在兼容现有 SSE 事件的前提下回传 session_id；验收连续两轮问题实际使用同一服务端会话与上下文。V1 只保留接口提供的 ID，没有修改后端。
- 真实联调：使用允许公开的业务数据，验证 MySQL、Milvus、Embedding、模型服务、真实角色权限和附件访问；建立可复现的召回与答案评测口径。
- 公网托管：单独选择托管平台、公开 API 策略及联系渠道，验证线上深链、HTTPS 与真实服务额度。当前只是可部署静态构建。
